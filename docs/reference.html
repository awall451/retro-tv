Gotchas found along the way

  • es.resolution must be in batocera.conf. The shutdown service S65values4boot copies it from batocera.conf into /boot/batocera-boot.conf on every reboot, so a value set only in the boot file is wiped. Set both.
  • EmulationStation doesn't rewrite es_settings.cfg on shutdown (tested), so editing it while the menu runs is safe. Stop the menu anyway before editing game lists.
  • Kodi rewrites add-on settings when it exits. Close Kodi before editing PM4K's settings.xml.
  • pgrep -f / pkill -f over SSH match their own command line. Use a bracket pattern such as grep "^/usr/bin/[r]etroarch". One pkill killed its own session.
  • Restarting the menu over SSH once took the display server down with the session. After /etc/init.d/S31emulationstation start, check from a new session that sway and emulationstation are running. Restarting the menu also stops a running scrape.
  • Relaunch the Control Center with setsid batocera-controlcenter hidden; calling the app directly fails with failed to create display. kill -10 $(cat /var/run/batocera-controlcenter.pid) shows or hides it.
  • Screenshots: grim captures the whole screen (with XDG_RUNTIME_DIR=/var/run WAYLAND_DISPLAY=wayland-1). To capture a game list, temporarily set StartupSystem=snes and StartupOnGameList=true in es_settings.cfg.
  • The menu's BIOS warning fires if any of a system's known BIOS versions is missing, even when the emulator has the one it needs.
  • Onion art can be truncated in a backup; check full PNG decoding, not just the header.

Troubleshooting

ProblemFix
No picture on the TrinitronConverter powered and on NTSC, TV on the Video input. Reboot the Pi with the converter already on. If still blank, add hdmi_force_hotplug=1 under [all] in /boot/config.txt (the BATOCERA drive with the card in a PC).
Picture rolls or is black and whiteConverter set to PAL; switch to NTSC.
Edges cut off on the TrinitronRe-measure with the overscan pattern and edit crt-margins.conf.
Wrong profile pickedChoose the other Ports entry; both work on either TV.
Controller won't connectAirplane mode: batocera-planemode disable then /etc/init.d/S32bluetooth restart.
Blank covers in a listCheck the menu log for invalid data; the PNG is broken. Rerun the import's art check or scrape that game.
/userdata on the card instead of the SSDfindmnt /userdata; check sharedevice=DEV <UUID> in batocera-boot.conf and that the SSD is detected (lsblk -f).
Can't reach batocera.localUse <pi-ip>.
Hot case, worried about throttlingvcgencmd measure_temp; vcgencmd get_throttled. 0x0 means no throttling since boot; the Pi slows itself at 80 °C.

Rebuilding from scratch, in order

  1. Flash the card (tools/flash-sd.ps1) and boot once.
  2. Install the SSH key, then move /userdata to the SSD (Base setup).
  3. Enable I2C and the Argon service; check the BIOS files.
  4. Stage and import each system, then PS1 (Game library).
  5. Copy pi/shaders/configs/* to /userdata/shaders/configs/ and pi/shaders/crt/*.glslp to /userdata/shaders/crt/.
  6. Copy pi/display-profiles/* to /userdata/system/display-profiles/ and pi/display-profiles/ports/* (the two scripts and gamelist.xml) to /userdata/roms/ports/, pi/kodi-skin/* to /userdata/system/display-profiles/kodi-skin/, and pi/scripts/* to /userdata/system/scripts/ (executable), then run apply.sh hdmi.
  7. Compare with pi/snapshots/ and set anything left: subset.optimizesmallscreens=no, CheckBiosesAtLaunch=false.
